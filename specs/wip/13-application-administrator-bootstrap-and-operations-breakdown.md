Pinned semantics (docstring is the spec-13 storage-transition contract): unknown user → `EntityNotFoundError`; stored role == `new_role` → `NO_CHANGE` with zero writes and the audit event **not** persisted (idempotent no-op); because `ApplicationRole` is a closed two-value vocabulary, a CAS miss on `expected_role` can only mean stored == `new_role`, so no third outcome exists (docstring tripwire: adding a third role requires revisiting this operation); a demotion `ADMIN → USER` whose target is `ACTIVE` is refused with `LastActiveAdministratorError` when no **other** `ACTIVE` admin user exists, fully rolled back (no role write, no audit row); a demotion of a `DISABLED` admin skips the guard (the active-admin count cannot change); on `TRANSITIONED` the role update and the caller-formed `audit_event` append commit in one transaction and the returned `User` is the final stored record with `new_role`/`updated_at` (read-back allowed — `revoke_api_key` precedent). Audit-parent integrity is pinned in the same docstring: when `audit_event.organization_id` is not `None` the transition enforces the same organizations-parent guarantee as `append_audit_event` — SQLite via the existing FK failure → `ReferenceNotFoundError` mapping, DynamoDB via an additional `ConditionCheck` on the organizations item inside the same `TransactWriteItems` (missing parent → `ReferenceNotFoundError`, full rollback: no role write, no audit row), closing the race where the organization is deleted between the task-3 anchor read and commit; `organization_id=None` → no parent check (the contract keeps org-less audits legal).
