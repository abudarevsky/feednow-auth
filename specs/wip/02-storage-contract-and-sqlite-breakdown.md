## Planner decisions (interpretation of the contract)

- **Sync protocol.** Spec §11's example and both target adapters (stdlib `sqlite3`, `boto3`) are synchronous; `Storage` is a `typing.Protocol` with sync methods. FastAPI runs sync calls through its threadpool; async would be an invented constraint.
- **No new dependencies.** Stdlib `sqlite3` only; SQLAlchemy is rejected (spec §11 lists "SQLAlchemy Session" as a leak example). Dev deps unchanged.
- **Storage never mints IDs or timestamps.** Every write receives a fully formed domain entity (`usr_`/`org_`/`key_`/`extid_`/`mem_`/`aud_` ids and `created_at`/`updated_at` are caller-populated). Phase 01 deliberately deferred generation strategies to Phases 03/05; a storage-side generator would become the de facto entropy contract. `revoke_api_key` likewise takes `revoked_at` from the caller (`utc_now` is the service clock source).
- **Domain error vocabulary.** `StorageError` base in `contract.py` with `EntityNotFoundError`, `DuplicateEntityError` (stable `kind` discriminator: `entity_id` | `external_identity` | `membership` | `organization_slug` | `user_email` | `api_key_id`), `ReferenceNotFoundError`, `InvalidCursorError`, and `DuplicateExternalIdentityError(DuplicateEntityError)` carrying `existing_user_id: UserId | None`. `entity_id` covers PRIMARY KEY (`id`) collisions on any of the six tables — every `create_*`/`append_*` can receive an already-persisted record id, and the four unique-index kinds do not express that; the contract docstring pins that a PK violation surfaces as `DuplicateEntityError(kind="entity_id")`, never a raw sqlite error. Adapters translate `sqlite3` exceptions; no sqlite3 type escapes `app/storage` (acceptance 1). HTTP mapping (404/409) is Phase 04+ work; `app/api` is untouched this phase.
- **Uniqueness set (owns the Phase 01 deferrals).** Unique indexes on `(provider, provider_subject, tenant_normalized)` (external identities), `(organization_id, user_id)` (memberships), `organization.slug`, and `user.email` — all four were explicitly deferred to Phase 02 by the Phase 01 model docstrings. Email/slug are constraints, never identities (AGENTS.md).
- **NULL tenant resolution (closes the Phase 01 handoff item).** The indexed tenant column stores a normalized empty string `''` when `provider_tenant is None`; the adapter maps `''` → `None` on read so domain objects keep `None`. The mapping is lossless because `ProviderTenant` pins `min_length=1` — `''` can never be a legitimate domain value. SQLite `UNIQUE` treats NULLs as distinct — without normalization duplicate `cognito` identities would slip through. `''` makes the constraint deterministic and gives Phase 06 the same semantics via a stored-attribute default. Flagged as a spec-revision proposal (Escalations).
- **Sortable timestamp encoding.** Timestamp columns store TEXT `YYYY-MM-DDTHH:MM:SS.ffffffZ` — fixed-width, microseconds always present (`isoformat(timespec="microseconds")`, `+00:00` → `Z`). `to_utc_rfc3339` omits zero-microsecond fields, which breaks lexicographic == chronological ordering that keyset pagination relies on, so adapters must not reuse it for stored columns. Read back with `datetime.fromisoformat` (accepts `Z` since 3.11).
- **Keyset pagination.** Lists order by `(created_at, id)` ascending; `id` is the unique tiebreaker making traversal deterministic. The cursor is opaque (base64url of the position key **plus a list-scope tag**, so a cursor from one list is invalid for another), created/decoded only inside `sqlite.py` (AGENTS.md: cursor opacity); tampered or malformed cursors raise `InvalidCursorError`, never `ValueError`/sqlite errors. Fetch `limit + 1` rows to decide `next_cursor`; the adapter re-clamps `limit` via `clamp_limit` as defense in depth below `PageParams`.
- **`list_user_organizations` is a domain operation.** Returns organizations where the user holds an **active** membership (disabled membership = suspension, per the pinned `MembershipStatus` semantics); the filter is pinned in the contract docstring and conformance. Phase 04 authorization re-checks roles.
- **Membership lookup keyed by the domain tuple.** `get_membership`/`delete_membership` take `(organization_id, user_id)`; the `mem_` record ID is never a lookup key (it never surfaces above storage). Delete is a physical delete (Phase 01 pinned); deleting a nonexistent membership raises `EntityNotFoundError` — whether the API answers 204 or 404 is a Phase 04 decision.
- **`revoke_api_key` is a first-write-wins CAS.** Conditional update `active → revoked`; concurrent/duplicate revocations return the stored key with the original `revoked_at` preserved (idempotent success, no error) — AGENTS.md requires revocation duplicate behavior to be defined and tested. Revoking a key id that does not exist raises `EntityNotFoundError` (only the active→revoked CAS is idempotent; absence is absence). `get_api_key_by_key_id` is keyed by the §8 credential segment (`KeyId`) with a UNIQUE index; contract docstrings disambiguate it from the `key_` application identity parameter of `get_api_key` (`ApiKeyId`) — the collision is already flagged in `src/app/api/schemas/manifest.py`. **Tenancy scoping is pinned:** `get_api_key`/`revoke_api_key` take only the `ApiKeyId` and return the full row regardless of organization (the §8 verification path must resolve the org *from* the key); enforcing the §14 org-scoped route contract is the Phase 05 service's check of `organization_id`, not a storage filter.
- **`provision_user` atomicity and retry.** `provision_user(*, user, identity, organization, membership, audit_events) -> ProvisionedUser` writes all rows in one transaction; `audit_events` is **required keyword-only** (the acceptance line names audit events as part of the atomic unit; no default may let a caller silently skip the §16 provisioning events). In the real §6 concurrent-first-login race both attempts carry the *same email* and the same identity tuple, so the loser's first UNIQUE violation is `users.email`, not the identity index: inside `provision_user`, **any** UNIQUE violation on `users.email` or the identity tuple is interpreted as a concurrent provisioning race and raises `DuplicateExternalIdentityError` (full rollback); `existing_user_id` is resolved post-rollback inside the adapter by re-reading the identity row for the supplied `(provider, provider_subject, tenant_normalized)` tuple, falling back to a users-by-email read within the same adapter call (no new contract method), else `None` — so Phase 03 converges without a second query. Other UNIQUE violations (organization slug, membership pair) propagate as their own `DuplicateEntityError` kinds; every failure path is fully rolled back.
- **Audit writes.** `append_audit_event` is a standalone contract method (one of the 18) returning `None` (pinned in the signature — no-mint/no-re-read: there is nothing to return), and must be implemented and conformance-tested on its own — §16 events like `membership.removed` and `api_key.revoked` are appended by Phase 03–05 services outside any compound operation; only provisioning batches go through `provision_user`. Single-row insert, FK check on `organization_id` → `ReferenceNotFoundError`, duplicate `aud_` id → `DuplicateEntityError(kind="entity_id")`, metadata stored via the JSON codec with exact round-trip. No read/list surface this phase (Escalations: Phase 08) — append is write-only by contract.
- **Referential integrity.** `PRAGMA foreign_keys=ON`; child rows with unknown parents (identity→user; membership→org+user; api_key→org+creator; audit→org) raise `ReferenceNotFoundError`. DynamoDB has no FKs: the contract docstring obligates Phase 06 to replicate the checks inside its conditional writes; conformance pins the observable behavior, not the mechanism.
- **JSON columns.** `scopes` is a TEXT JSON array with exact round-trip (order and duplicates preserved — normalization is Phase 05 domain work); `audit.metadata` is a TEXT JSON object (already JSON-safe at the model boundary). Enums store as exact `StrEnum` strings; row→domain reconstruction goes through `model_validate`, so corrupt stored values fail loudly (documented tripwire, not silent coercion).
- **Connection model.** `SQLiteStorage(path)`: thread-local connections, `journal_mode=WAL`, `busy_timeout` (5 s), idempotent schema init stamped with `PRAGMA user_version`; `close()` releases. Factory `open_sqlite_storage(path) -> Storage` is the documented entry point (handoff requirement). Concurrency tests use barriers + WAL, never sleeps.
- **Conformance suite shape (Phase 06 reuse contract).** Adapter-neutral suite in `src/tests/storage_contract/suite.py`: plain test functions against a `storage` fixture, importing only `app.storage.contract` and `app.models` (asserted by test) so Phase 06 runs the module unchanged against DynamoDB Local. Suite builders (`make_user`, `make_organization`, …) live in `suite.py` itself and construct domain objects with **literal prefix-valid IDs and fixed literal timestamps** — no generators and no `utc_now()` (this is how the suite honors "storage never mints IDs" and the Phase 03/05 entropy deferral while staying deterministic; `usr_test_0001`-style literals validate against `ID_SUFFIX_PATTERN`). `suite.py`'s module docstring states the fixture contract Phase 06 must satisfy: *the `storage` fixture yields an initialized adapter with all tables empty, per test* (SQLite entry: fresh temp file via the factory; DynamoDB entry: equivalent isolation). The SQLite entry `test_sqlite_contract.py` provides that fixture. Storage *behavior* is tested only in the suite; `tests/unit/` covers pure helpers (codecs, mappers, error translation, contract surface).
- **Memory fake deferred.** The work boundary says "only where it helps unit tests" — no Phase 02 unit test needs one. `memory.py` defers to the first phase with a unit-test need (likely 03/04); recorded as an escalation so the deferral is explicit rather than silently dropped from spec §11's file list.
