## Planner decisions (interpretation of the contract)

1. **The frozen surface is untouched — zero storage-contract changes.** Phase 02 already shipped the complete API-key persistence surface: `create_api_key`, `get_api_key` (by `key_` identity, deliberately org-unfiltered — the service enforces tenancy), `get_api_key_by_key_id` (§8 credential-segment point lookup), `list_api_keys` (org-scoped, all statuses, `(created_at, id)` order), and `revoke_api_key` (first-write-wins CAS, idempotent success, original `revoked_at` preserved, absence is `EntityNotFoundError`). `append_audit_event`'s docstring **names `api_key.revoked` as its intended Phase 05 standalone user**. The phase spec's generic task "update storage contract" is therefore discharged as *no new methods needed* — the 19-method protocol is consumed as-published, and Phase 06 inherits **no** new compound-replication obligation from Phase 05. AGENTS.md's "define and test atomicity and duplicate-request behavior" is satisfied by definition, not by a 20th method: creation is one row + one post-commit audit (single-row write is atomic; the key-created-audit-missing window is the Phase 04 decision-7 accepted limitation, documented); creation is **non-idempotent by design** (every POST mints a fresh credential — no client token invented); revocation's CAS is the idempotent duplicate path (decision 10).

2. **Credential format (Phase 05 owns what Phase 01 deferred; spec §8 "recommended" made concrete).** Literal `fn_<live|test>_<key-id>_<secret>`:
   - `<key-id>`: 26-char **ULID** (48-bit ms timestamp + 80-bit `secrets`-drawn randomness, Crockford base32, uppercase, alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ` — contains no `_`, which is what makes parsing unambiguous). Satisfies the `KeyId` ≤64 bound; uniqueness is proven by the storage UNIQUE index (collision → 409, decision 11), not by entropy alone.
   - `<secret>`: `secrets.token_urlsafe(32)` — exactly **256 bits** of CSPRNG entropy, 43 base64url chars. The alphabet includes `_`, so parsing is: strip the fixed 8-char env prefix, split at the **first** `_` (key-id segment, underscore-free by charset), everything after is the secret (may contain `_`).
   - `key_prefix` display rule (Phase 01 deferred it): `fn_<env>_<key-id>_<first 6 secret chars>...` (≤64 ✓; key-id is non-secret by §8 design, 6 chars of a 43-char secret is display-masked).
   - `secret_hash`: `HMAC-SHA256(pepper, secret)` **lowercase hex** (Phase 01 left the encoding open; hex pinned here).
   - The `key_` application ID: `new_api_key_id()` added to `services/idgen.py` (same `prefix + "_" + uuid4().hex` strategy; the idgen docstring explicitly defers `key_` to Phase 05 — this discharges that half of the deferral; the §8 credential segment stays in `auth/credentials.py`, **not** idgen, so credential entropy never masquerades as application-ID entropy).
   - Full literal length: 8 + 26 + 1 + 43 = 78 ≤ the frozen `FullApiKey` 512 bound.

3. **Pepper through an injectable abstraction; no import-time config, no AWS import.** `src/app/auth/pepper.py`: `PepperSource` runtime-checkable `Protocol` with `current() -> bytes`; `StaticPepper` implementation validating **≥ 32 bytes** at construction and redacting itself everywhere (`__repr__`/`__str__` → `StaticPepper(<redacted>)`, never in exception messages, never logged/persisted/audited). Construction is pure (boot contract). Tests inject `StaticPepper`; **Phase 07** wires the AWS Secrets Manager implementation at the deployment entrypoint behind the same protocol — the no-`boto3`-in-`sys.modules` proof stays green because everything shipped in Phase 05 is stdlib (`hmac`, `hashlib`, `secrets`, `time`, `uuid`). Pepper rotation is a non-goal (one current version; `current()` is the seam that makes future rotation additive).

4. **Verification pipeline (spec §8 flow) and one uniform 401 — no failure oracle.** Fixed order: (a) parse literal (bad env prefix, missing/empty segments, key-id outside the Crockford 26-char shape, empty secret → format failure); (b) `get_api_key_by_key_id` — on `EntityNotFoundError` the pipeline still performs a **dummy constant-time comparison** of the supplied secret's HMAC against a fixed same-shape digest before failing (equalizes the unknown-key timing branch; the AC's "without leaking which secret segment failed" is honored on both the message *and* timing axes); (c) `hmac.compare_digest` of recomputed vs stored hash; (d) parsed env must equal stored `environment` (defense in depth against inconsistent rows); (e) `status is ACTIVE`; (f) `expires_at` is `None` or in the future (expiry **derived**, per the pinned enum decision — never a stored status). Every failure raises one `ApiKeyAuthenticationError` with the single fixed message `"invalid API key credentials"` → **401** `unauthenticated`; no branch-specific message, no key-id/secret/pepper material in any error, log, or audit. **Organization status and scopes are authorization, not authentication** — checked in the access dependency (decision 6), where denials get the Phase 04 uniform 403 + audit. `last_used_at` is **never written**: verification is read-only by design (the handoff's "no synchronous feednow-auth calls on every request" plus zero write amplification); the field stays `None` on every API-served row — escalated to §16/Phase 08, not silently dropped.

5. **API-key `AuthorizationContext` (spec §10; AC 4).** `build_api_key_context(api_key)`: `actor_type="api_key"`, `actor_id=api_key.id` (the `key_` application identity — never `usr_`, never the record's `key_id` segment), `organization_id=api_key.organization_id`, `roles=[]` **always** (the creator's memberships are never consulted — this is the structural "no human role escalation" proof), `scopes=` the key's stored (normalized) scopes. Human contexts are unchanged (Phase 03 `build_user_context`, `scopes=[]` stays empty for humans).

6. **Principal dispatch + the documented `organization_access` extension point.** New frozen `Principal` dataclass (`src/app/auth/principal.py`): `user: User | None`, `api_key: ApiKey | None`, `context: AuthorizationContext` (exactly one of user/api_key is set, enforced in `__post_init__`; on the human path it wraps the unchanged Phase 03 `ResolvedIdentity`). `build_current_principal(storage, verifier, pepper_source)` (`src/app/auth/dependencies.py`): extracts the bearer token via the existing `_extract_bearer_token`, then **dispatches on the literal prefix** `fn_live_`/`fn_test_` → API-key path (verify + context, failure → uniform 401); anything else → the unchanged Phase 03 chain. Prefix collision is impossible (JWS compact tokens always start `eyJ` — base64url of `{"`), documented. `organization_access` factories gain a **keyword-only `pepper_source: PepperSource | None = None`**: when `None` they compose exactly the Phase 03 chain (byte-stable regression: all Phase 04 tests pass **unchanged**, and a `fn_` literal on those routes simply fails JWT verification → 401); when provided, they compose `build_current_principal` and a non-`user` actor is refused with the uniform 403 **audited** `authorization.denied` reason `human_only` (generalized actor, decision 7). New factory `build_organization_scope_dependency(storage, verifier, pepper_source, required_scope, operation_id) -> PrincipalAccess` (new frozen dataclass: `principal`, `organization`) — **the Phase 06/07/08 handoff**: human branch = Phase 04 member-rank rules (roles govern, `required_scope` never applies to humans); API-key branch = org status → `api_key.organization_id == path org` → exact-string membership of `required_scope` in the context's scopes; every denial is the same uniform 403 body with its deterministic audit reason. `OrganizationAccess.membership` stays **non-optional** (Phase 04 type frozen — no shipped consumer reads it for keys because keys never receive `OrganizationAccess`; `PrincipalAccess` is the key-carrying type).

7. **Denial-audit generalization + reason vocabulary (explicit current-phase contract extension, not smuggled).** `build_denial_audit`/`audit_denial` (`services/authorization.py`) widen `actor_user_id: UserId` → `actor_id: ActorId` and derive `actor_type` from the concrete class via a new tiny model-layer helper `actor_type_for(actor_id: ActorId) -> ActorType` (`models/authorization_context.py`, additive; complements the existing `ensure_actor_id_matches_actor_type` single source). `AccessOutcome` gains exactly three denial strings — `human_only`, `organization_mismatch`, `insufficient_scope` — added to `DENIAL_REASONS`; the metadata shape stays `{"reason", "operation"}` (the Phase 04 §16 escalation pin). Existing Phase 04 call sites/tests keep passing (positional `(storage, actor, org, reason, operation)` unchanged — parameter rename only). API-key scope enforcement is **exact string match**, no wildcards, no hierarchy (spec §9 defines none; inventing `vispector:*` would be smuggled entitlement semantics — escalated instead).

8. **Management role policy (extends Phase 04 decision 3 to the new routes).** `GET .../api-keys` → member dependency (rank ≥ viewer); `POST .../api-keys` and `DELETE .../api-keys/{key_id}` → admin dependency (rank ≥ admin). Routers pass `pepper_source` so the key-rejection branch is live: an API key calling any management route gets the uniform 403 + `human_only` audit (AC 4's escalation proof). Path `{key_id}` carries the **`key_` application identity** (`ApiKeyId`) per the frozen manifest and `ApiKeySummary.id` — never the §8 credential segment (the manifest docstring pins this collision; the segment never appears in any path or response).

9. **Creation flow (service `create_api_key`, injectable `storage`/`now`/`pepper`/`ids`).** Normalize request scopes to **sorted unique** before persisting (the Phase 02 contract defers normalization to Phase 05; storage then round-trips exactly) → mint `key_` id, ULID key-id, 256-bit secret → build the complete `ApiKey` (`status=ACTIVE`, `created_by_user_id=` caller `usr_`, `key_prefix` per decision 2, `secret_hash` per decision 2/3, `expires_at=None` — the frozen §15 request schema has no expiry field, escalated) → `storage.create_api_key` → on success append `api_key.created` (metadata exactly `{"environment": <live|test>, "scopes": [<sorted scopes>]}` — non-secret; target `api_key`/the `key_` id; actor the human `usr_`) → return `(api_key, full_literal)`; the **router** is the only place the literal crosses into `ApiKeyCreatedResponse.key` (201), exactly once. Audit-append failure → 500 with the key persisted and the plaintext lost (documented decision-1 window). List: pass-through `list_api_keys`, project field-by-field to `ApiKeySummary` preserving `limit`/`next_cursor` verbatim (Phase 04 decision-8 pattern); summaries carry **no** `secret_hash`, no plaintext, no raw key-id segment.

10. **Revocation flow.** Admin dependency → `get_api_key(path id)` (`EntityNotFoundError` → domain `ApiKeyNotFoundError` → 404) → **`api_key.organization_id != path org` → the same 404 with the same fixed message** (no cross-org existence oracle; AC's isolation proof) → `storage.revoke_api_key(id, revoked_at=now)` (CAS: already-revoked is an **idempotent success**, original `revoked_at` preserved) → append `api_key.revoked` (metadata exactly `{}`; target the `key_` id) → **204** empty body (manifest-pinned). Duplicate/concurrent revocations each append one truthful audit row (each processed 204 *is* one audited action; suppressing the loser's audit would need winner-detection that same-clock ties defeat — defined, tested, documented). "Immediately effective" is structural: verification reads stored truth per request (no cache in this service), so the next request after the CAS sees `status=revoked` → 401.

11. **Error mapping (frozen envelope codes only).** Scope/name/environment shape failures → **422** via the frozen `RequestValidationError` handler (schemas are the single validator; `SCOPE_PATTERN` is reused, never re-declared). Invalid cursor → **400** `validation_error` (Phase 04 precedent). `DuplicateEntityError(kind=api_key_id | entity_id)` from create (ULID/uuid4 collision — astronomically rare but the UNIQUE index is the arbiter) → **409** `conflict` with a fixed retry message. Unknown/foreign key on revoke → **404** `not_found`. All auth failures → **401** `unauthenticated` (decision 4); all access denials → the one uniform **403** `forbidden` body (Phase 04 decision 4 — byte-identical across all eight denial reasons now). Any other `StorageError` → untranslated → frozen 500. Fixed messages only; no caller text, no credential material echoed.

12. **Test strategy (mirrors the proven Phase 03/04 stack).** Unit: pure credential functions (format round-trips, ULID shape/uniqueness, parse with `_`-bearing secrets, HMAC determinism, dummy-compare path taken, pepper masking/length), stub-`Storage` service tests (zero-write proofs, exact audit shapes, injected clock/ids), context builder (`roles == []`). Integration: `TestClient(create_app(routers=[...]))` with the signed-token + loopback `JwksTestServer` fixtures from `src/tests/support/cognito.py` (never live Cognito), real SQLite, Phase 04 seeded users/orgs/memberships (`create_api_key` targets seeded `usr_`s), `StaticPepper` injected; **probe routers defined in the test module** exercise `build_organization_scope_dependency` (shipped routers register manifest entries only). Expired keys are **seeded directly** (no API path exists — decision 9). Audit and row assertions read SQLite directly (no audit read surface). Concurrency: `threading.Barrier`, no sleeps, 20 repeats, main-thread warm-up. Every denial/401 case asserts byte-identical bodies (oracle-freedom) and, where the org row exists, the audit row; every secret-bearing path is followed by a substring sweep (no literal/secret/pepper bytes in any stored row, log record, or error body).
